01
The claim

What "one of the best" actually means at this size

At ~0.4–0.6B parameters, a model cannot be good at everything — capacity is the binding constraint. So "best" has to be a claim about a target, measured honestly against real rivals. Ours is precise:

For Italian agentic tool use in the sub-billion class, Nesso2-0.4B-Agentic is the strongest open model we could find — it wins our agentic benchmark outright, leads decisively in Italian, and does so without giving up Italian knowledge or conversational quality. It is not the best at English tool use (Qwen3-0.6B keeps that), and it does not out-know a model trained on far more data. We show all of it below.

The rest of this report is the evidence: how the model was built, how we measured it against five other models across three independent evaluation families, the iteration curve that got us from 61 to 68, and — because a report that only lists wins isn't evidence — the experiments that regressed and what they taught us.

02
The build

Five phases, not one fine-tune

A tiny model earns both knowledge and agentic skill only if the pipeline gives it each on purpose. The pivotal work happened before the agentic tuning — in continued pre-training — and it is the part usually left out.

PHASE 0

The base — and the wall

Zagreus-0.4B-ita: ~350M parameters, pre-trained from scratch on ~1T tokens (≈400B English, 400B Italian, 200B code). One fact set the whole agenda — across all ~775k pre-training steps, MMLU never left chance (~0.25). A small model trained on web text does not acquire exam knowledge. That is the wall.

64× A100 · Seeweb HPC · Nanotron
PHASE 1

Proving it is a pretraining wall

Hypothesis: post-training can supply the missing knowledge. Experiment: SFT, then mixed on-policy distillation from a nesso-3B teacher, then a focused MMLU-only run. Result: a wash — Italian MMLU 0.258 → 0.264; even the focused run bought only +2. But it exposed the key fact: the entire gap to Qwen was MMLU (we already beat it on Italian HellaSwag/ARC). Post-training reweights; it cannot install facts. CPT is the only lever.

A100 · palingenesis · on-policy distillation
PHASE 2

Breaking the wall — the CPT program

Hypothesis: CPT on knowledge-dense, extractable data can install the facts, with replay to prevent forgetting. Experiment: a two-tier corpus — ~52M tokens of ready-made QA, plus ~2B tokens from 2.47M Wikipedia passages QA-augmented by Qwen3.6-35B (grounded QA + a multiple-choice + a summary each). Resume the base, re-warm the LR, train a 50/50 knowledge/replay blend — a 1.5B-token probe, then a 4.46B-token definitive run. Result: the wall came down (below).

Seeweb HPC · Nanotron · 50/50 knowledge/replay
PHASE 3

32k context — without losing the knowledge

Hypothesis: an agent must hold tool schemas, observations and trajectories in context. Experiment: attention-scaling — raise RoPE θ 10k → 1e6, adapt on 1.44B long-document tokens with 15% knowledge replay as a guard. Result: retention held — MMLU dropped only 0.9–1.6 points, commonsense flat-to-up. 32k came essentially free.

Seeweb HPC · RoPE θ = 1e6
PHASE 4

Agentic SFT — five iterations (this model)

Supervised fine-tuning on the 32k knowledge base: bilingual instruction data plus a synthetic function-calling corpus with randomized tool schemas (single/parallel calls, disambiguation, missing-argument, unavailable-tool refusal, observation grounding, multi-step, and no-tool discrimination). It took five iterations, v3 → v8, to balance — the full story is in The iteration below.

03
Method

How we measured — three independent families

One benchmark proves nothing. We evaluate every candidate on three families that stress different things, then read them together — because at 0.4B they often disagree, and the disagreement is the signal.

Family A

Academic

Standard knowledge & reasoning, Italian and English, via our lm-evaluation-harness fork.

  • MMLU — 5-shot acc
  • HellaSwag / ARC — 0-shot acc_norm
  • IFEval — instruction-level, generative
Family B1

Agentic function calling

A frozen, bilingual 100-case suite — 10 categories, 50 Italian / 50 English — scored by an automatic per-category grader.

  • Format — Hermes <tool_call> JSON
  • Decoding — pure greedy
  • Tools — randomized schemas
Family B2

Conversation (LLM-judge)

20 multi-turn tasks per language, graded 1–10 on correctness, language-fidelity and helpfulness.

  • Judge — Qwen3.6-35B-A3B
  • Answers — greedy
  • Axes — 3, absolute scale

Six models sit in the comparison set throughout: our agentic line (v3, v6, v6.1, v7 and the released v8 = Nesso2), plus Qwen3-0.6B as the external rival. The conversation family additionally includes the reference nesso-0.4B-agentic.

07
The iteration

From 61 to 68 — a zero-sum budget, spent deliberately

The core lesson of this project: at 0.4B the training-data budget is zero-sum. Some agentic skills are data-responsive (more examples move them); others are capacity-bound (they don't budge no matter how much you add). Progress came from identifying which is which, and refusing to spend budget on the latter.

v3

The strong-but-trigger-happy baseline

SFT on filtered Italian data + agentic. Excellent single/parallel calls, but over-fires: it reaches for tools when it shouldn't.

v5

Tested a ChatML template with warm-initialized new tokens. Lost to the Llama-3 template on every axis. Dropped.

Tried to improve everything at once, thinning the budget across capacity-bound categories. Tied for last. Proof that spreading effort is worse than concentrating it.

v8

The focused fix = Nesso2 released

One data-responsive target, done richly: 4.5× more no-tool examples (with the tempting tool present, answered naturally), budget reclaimed from capacity-bound categories, multi-step kept. No-tool 2→7, multi-step 1→6, firing held.

68/100
The insight, in one line

The last mile at 0.4B wasn't more data — it was one data-responsive skill, trained richly and naturally, with budget stolen from skills that don't respond to data.

This is the transferable recipe we carry to the 3B model: diagnose responsiveness first, then concentrate.

08
What didn't work

The negative results — because evidence needs them

Every claim above is stronger for the experiments that failed around it. These are the ones we kept notes on.

✕ Spreading the budget (v7)

Improving every category at once lowered the total to 61 — thinning data-responsive wins to fund capacity-bound categories that never moved.

Lesson: concentrate budget on one responsive target, not many.

✕ DPO on the v3 checkpoint

Preference-tuning toward "more detailed" answers cut conversation quality from 4.25 to 3.48 for a +0.008 IFEval gain — at 0.4B, "more detailed" becomes hallucination.

Lesson: ship the SFT; DPO for verbosity backfires at this scale.

✕ ChatML + embedding resize (v5)

New special tokens, warm-initialized, on a ChatML template lost to the plain Llama-3 template across the board.

Lesson: don't pay a re-embedding cost for a template the base never saw.

✕ Repetition penalty on tool calls

Our chat-tuned decoding (rep_penalty 1.15) corrupted tool JSON — the template echoes name/arguments, so the penalty suppressed exactly those tokens, emitting "Name" or dropping arguments.

Lesson: pure greedy for structured output; save the penalty for prose.
09
Honest caveats

Where Nesso2 is not the answer

The specialization is a real trade, and integrity means naming it:

English tool use. Qwen3-0.6B leads (38 vs 33 / 50). If your agent runs primarily in English, it is the stronger pick.

Observation grounding regressed. The no-tool "answer directly" data bled into one category — reading a tool result and responding from it — dropping it 8→3 in the benchmark. Notably this did not appear in the conversation judge (correctness actually rose), so we read it as a narrow eval-format artifact rather than a capability loss; we flag it anyway.

Raw knowledge. On English MMLU, a model trained on far more data stays ahead. Nesso2's knowledge win is specifically Italian, and specifically relative to its own class.

Reproduce it

Run the model, run the benchmarks

The academic suite is public; the model card carries the full per-task table and working inference code. A single-tool call, verified:

# pure greedy — no repetition penalty for tool calls
prompt = tokenizer.apply_chat_template(
    messages, tools=tools, tokenize=False, add_generation_prompt=True)
inputs = tokenizer(prompt, return_tensors="pt", add_special_tokens=True)
out = model.generate(**inputs, do_sample=False, max_new_tokens=256)

# -> <tool_call>{"name": "get_weather", "arguments": {"city": "Milano"}}</tool_call>

Academic benchmarks were run with the mii-llm lm-evaluation-harness fork. The agentic and conversation suites are internal; methodology is described in Section 03.
